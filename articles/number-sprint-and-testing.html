Number Sprint: a 30-move twist on tile merging

Tile-merging puzzles — the "combine two matching tiles to get a bigger one" family — are about as proven a genre as browser games get. The problem, for us, is that a good run can go on for a very long time. That's fine for a game someone sits down with, but it fights against everything else we're building toward: something you can finish in the gap you actually have.

The fix: a hard move limit

Number Sprint plays like the tile-mergers you already know, with one change: you get exactly 30 moves. There's no "until you get stuck" — the run ends on move 30 regardless, and your score is however far you got. It turns an open-ended puzzle into something closer to a 2-to-4-minute sprint, which is also why it's the "longer" option on the site so far, next to two games built for under a minute.

Testing the merge logic before shipping

The trickiest part of this genre isn't the UI, it's the merge rule: each tile should combine with at most one neighbor per move, in the direction you swiped, without double-merging a tile that was already the result of a merge that same move. It's an easy rule to get subtly wrong.

Rather than only eyeballing it in the browser, we pulled the merge logic out and ran it against a set of fixed board states with known correct outcomes — a row of four identical tiles should collapse to two, not one; a column that's already full with no valid merges should correctly report "no move available" in every direction. Eleven cases, all passing, before this ever touched a screen.
